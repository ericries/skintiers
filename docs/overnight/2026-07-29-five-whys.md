# Five-whys: recurring patterns and durable guardrails

**Date:** 2026-07-29 · **Inputs:** QC findings (2026-07-29-qc-findings.md), review-feedback.yaml,
review-log.yaml, writing-guide.md, `git log -40`, the stuck-drafts postmortem (2026-07-28).
**Goal:** for each recurring class, drive to the systemic root and propose a guardrail that catches the
whole class **automatically**, so no critic or human is the last line of defence. Written from the main
loop during a spend-limit pause; the tooling itself is the *next* pass (do not implement large changes here).

**Guiding principle (from the stuck-drafts fix):** when a workflow's intended terminal state and its
enforced state differ, add a detector that exits non-zero — prose in a guide is not a guardrail. Most
patterns below are the same shape: a rule exists in the writing guide, but nothing *rejects* a violation.

---

## Pattern 1 — House-voice violations (site self-reference, defensive meta, process language) reach published pages
Recurring: cross-queue drain needed a sitewide sweep to remove "SkinTiers"/"not our verdict"; QC 2/5 still
had to grep for them; critics keep catching "This page grades…", "Quarantined and discounted."
- **Why?** They are written by drafters and only caught downstream by a critic or a manual grep.
- **Why?** The critic is a probabilistic reviewer, not a deterministic gate; it misses instances.
- **Why?** There is no `sk lint`/`sk style` rule that *rejects* these fixed phrases.
- **Why?** The rules live only as prose in writing-guide.md / anti-ai-ese.md.
- **Root cause:** a *documented* rule with no *executable* enforcement. Every such rule leaks at the drafter's
  error rate.
- **Guardrail (automate):** add a `sk style` (or new `sk voice`) check with a deny-list, run in CI and as a
  publish gate:
  - site self-reference: reject `SkinTiers` in the body (frontmatter/templates exempt).
  - defensive meta: reject `not a (verdict|finding|SkinTiers)`, `not our verdict`, `What follows is`,
    `a matching INCI is not proof`, `This page grades`, `Ranked by controlled evidence.`,
    `Quarantined and discounted.` as line-leading fragments.
  - process/roadmap: reject `queued`, `a later phase`, `coming soon`, `not yet on the site`, `in a future phase`.
  - Whitelist substantive uses (e.g. "not a finding of harm" — see QC 2/5 false positives): match
    `not a finding` only when NOT followed by `of harm`.
  - **Test:** `tests/test_sk_voice.py` with a fixture page per phrase asserting non-zero exit.

## Pattern 2 — `sk style` findings are WARNINGS, so they don't block publish (en/em-dashes leaked to 16 pages)
- **Why?** 16 published pages carry connector dashes and "pivotal".
- **Why?** `sk style` emits `WARN`, and `sk publish` does not gate on style at all.
- **Why?** Style was treated as advisory polish, not a correctness gate.
- **Why?** Only `sk lint` (footnotes/xrefs) and a critic verdict gate publish; style sits outside the gate.
- **Root cause:** the publish gate and the style checker are disjoint. A WARN is a suggestion nobody must act on.
- **Guardrail (automate):** (a) `sk publish SLUG` runs `sk style` and refuses on any finding (with `--force`
  escape hatch, like the review-verdict gate). (b) Promote the dash/AI-ese checks from WARN to ERROR.
  (c) `sk audit` gains a "published-but-fails-style" category. **Test:** publish of a dashed fixture exits
  non-zero without `--force`.

## Pattern 3 — Missing required sections per page type (8 product pages lack `## Summary`)
Also: condition pages historically lacked "How to know you have this" until retrofitted this session.
- **Why?** Batch-3/old pages predate the summary-first + how-to-know standards.
- **Why?** Nothing checks that a page of type X contains its required sections.
- **Why?** `sk lint` validates frontmatter + footnotes, not body structure.
- **Root cause:** structural requirements are conventions, not validated invariants.
- **Guardrail (automate):** `sk lint` gains a per-type required-section check:
  `product` → `## Summary`; `condition` → `How to know you have this`; `study` → a detailed-summary body;
  driven by a small `REQUIRED_SECTIONS = {type: [heading substrings]}` map in sklib. Exit non-zero if
  missing. **Test:** a product fixture without `## Summary` fails lint. (Closes review-queue #10's silent gap.)

## Pattern 4 — Load-bearing claims rest on anti-bot / paywalled sources that can't be re-verified
Recurring holds: some-by-mi (iHerb 403), LRP Effaclar Mat (US page 403 even via residential proxy), atopic
(journal full text). Also fabrication risk when the source can't be checked (octocrylene FDA misattribution).
- **Why?** The primary source (retailer/manufacturer/journal) blocks automated fetch.
- **Why?** `sk verify` uses a plain fetch that WAFs 403, so the critic can't re-confirm the quote/stat.
- **Why?** There was no anti-bot fetch path until Apify was wired in this session.
- **Why?** Even now, `sk verify` doesn't route through Apify, and nothing records *which* sources are
  verify-blocked so they can be re-checked.
- **Root cause:** verification depends on a fetch channel that a whole class of important sources defeats.
- **Guardrail (automate):** (a) teach `sk verify` an Apify fallback (rag-web-browser) when a domain 403s,
  behind a flag; (b) maintain `data/anti-bot-domains.yaml` so verify auto-flags claims resting solely on a
  blocked domain and requires a second fetchable corroborator (the LRP→Amazon pattern used this session);
  (c) writing-guide rule (add now): *a manufacturer-only marketing stat needs a second, independently
  fetchable corroborating source, or it is softened/removed.*

## Pattern 5 — Uncited or mis-cited statistics inside `## The Evidence` (wrong denominators, claims their own source contradicts)
Recurring: acne "rank 15 of 49" (source ranks 41), acne BPO claim contradicted by Kawashima 2017,
tretinoin "similar" misquote, "uncited statistic in paragraph" WARNs.
- **Why?** Numbers are transcribed/paraphrased by a drafter and only re-checked by a critic re-fetch.
- **Why?** `sk verify` flags an *uncited* statistic (WARN) but cannot check that a *cited* number matches
  its source, and the WARN doesn't block.
- **Why?** There is no machine link between a `[^n]` and the specific figure it must support.
- **Root cause:** statistic↔source fidelity is a human/critic judgement with no deterministic support.
- **Guardrail (partial automate):** (a) promote "uncited statistic in `## The Evidence`" from WARN to ERROR
  (every number in that section must carry a `[^n]`); (b) `sk lint` rule: a paragraph containing `%`, a CI,
  or `n=` must contain a footnote marker. Full fidelity stays a critic job, but "unfootnoted number" becomes
  impossible. **Test:** an Evidence paragraph with a bare `%` and no `[^n]` fails.

## Pattern 6 — Cross-refs to pages that don't exist yet (9 targets render as plain text)
- **Why?** Pages link `[[future-page]]` before that page is authored (sunscreen filters, dupe products).
- **Why?** `linkify_xrefs` silently renders unknown slugs as plain text — no error, no queue entry.
- **Why?** There's no reconciliation between dangling xrefs and the research queue.
- **Root cause:** a dangling xref is invisible and untracked; it neither breaks nor gets scheduled.
- **Guardrail (automate):** `sk lint` (or `sk audit`) lists dangling `[[slug]]` targets; optionally
  `sk queue-add` each as a discovered demand so the link becomes a scheduled stub. Keep as a report (not a
  hard failure — dangling xrefs are allowed), but never silent. **Test:** audit surfaces a known dangling slug.

## Pattern 7 — Photo/image integrity (hotlinks, missing files)
Standard is self-hosted images in `static/images/`; hotlinking retailer URLs breaks and violates the standard.
- **Why?** An `images:` entry can reference a remote URL or a filename that isn't committed.
- **Why?** Nothing validates that each `images[].file` exists on disk and is a local path.
- **Root cause:** image references are unchecked frontmatter.
- **Guardrail (automate):** `sk lint` rule: every `images[].file` resolves to an existing file under
  `static/images/` and is not an `http(s)://` URL; `source`/`source_url` present for provenance. **Test:** a
  product fixture citing a missing image file fails lint.

## Already fixed this session (the model to copy)
- **Drafted-but-unshipped** → `sk audit` + build warning + definition-of-done (postmortem 2026-07-28). This is
  the template for every guardrail above: a deterministic check that exits non-zero, plus a test, plus a CI/build
  surface.

## Recommended implementation order for the tooling pass (4/5)
1. Pattern 1 + 2 (voice deny-list + style-blocks-publish) — biggest class caught, lowest risk. 
2. Pattern 3 (required sections) — closes a known structural gap with a tiny map + test.
3. Pattern 7 (image integrity) and Pattern 5 (unfootnoted numbers) — small, high-value lint rules.
4. Pattern 6 (dangling-xref report) — fold into `sk audit`.
5. Pattern 4 (Apify verify fallback) — largest; do last, behind a flag.

Every item ships with a test and, where it gates publish, a `--force` escape hatch consistent with the
existing review-verdict gate.
